# Prospective cross-layer decision evaluation

## Eligibility before any live pair

This protocol does not establish that a new fixture is suitable or that Jev helps. VCR-260 strategy and test-order audits found no justified new comparison in the existing fixtures. Coarse strategy labels cannot distinguish task-specific contract/dependency facts. Previous boundary and calculation cases were locally obvious or gave both checks the same relevant defect coverage.

A new cross-layer case must demonstrate that unit and integration checks detect distinct plausible defects through disposable, predefined mutants. Both baseline and treatment receive identical contracts, commands and measured metadata. The full suite remains mandatory regardless of ordering. Do not label coverage indirectly, hide useful evidence from baseline, add sleeps or inflate workloads to force a remote choice.

Before deciding to run, measure candidate commands on the unchanged fixture with the same interpreter and environment. Publish per-candidate samples, exit status, timing dispersion and immutable fixture hash. Use unknown runtime when buckets are unstable. Assess both coverage and duration; a faster check that covers all relevant defects dominates locally. Distinct coverage alone is not proof that a remote choice adds value. Confirm the actual source selector remains eligible with truthful metadata. If it abstains or a straightforward local heuristic resolves the ordering, record that outcome and do not force a provider request.

## Freeze before selecting or observing model output

- Pin host/CLI, model, reasoning effort, timeout and randomized arm order.
- Freeze task prompt, allowed source changes, immutable files, candidate commands, mandatory commands and independent expected behavior.
- Declare the baseline's reasonable local ordering policy in advance. Do not compare only against an intentionally bad order.
- Freeze defect-specific failure identifiers independently of selected advice; a nonzero exit is not automatically a useful error.
- Keep identical task evidence and permissions in both arms. State whether advice is injected before launch or requested inside the agent, and score native host delivery separately.
- Record advisor preparation and local evidence collection cost. Include them in elapsed completion; retain agent-only and independently validated completion separately.

## Outcome gates

Require actual focused and full execution evidence, preserved contracts/tests, independently correct final artifacts and advice acknowledgment before first selection for delivery credit. Never substitute a green starter suite for independent checks. Withhold validated completion if any quality or mandatory execution gate fails.

Useful-error timing requires a completed, matched candidate invocation whose output contains a frozen relevant failure identifier. Count each bounded event ID once. Do not infer it from first tool start, generic failure text, a later summary or an unrelated fixture's marker. If the first edit is correct and no useful failure appears, report null; do not seed an extra failure to manufacture this metric.

Report both arms, invalid cases and abstentions. Preserve input/cached/output tokens and validated provider usage. Unknown billing stays unknown. One successful pair does not prove repeatability, and local routing does not prove remote Jev efficacy. Any repeated evaluation must be specified prospectively rather than rerunning until a favorable result appears.
