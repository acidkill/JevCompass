# JevCompass roadmap

**Read by stage:** [current pilot evidence](PILOT.md) · [20-case design (not execution)](PILOT_CASES.md) · [release/task receipts](TASKS.md) · [quick start](README.md).

The Apache-2.0-licensed [GitHub releases](https://github.com/acidkill/JevCompass/releases) contain a reviewed local catalog, two default nonblocking Codex hooks, optional OpenRouter Decisions ranking, explicit recommendations, an installer, and diagnostics. PyPI v0.1.17 added explicit custom-skill curation; published v0.1.18 corrects its privacy disclosure and the four-document release gate is enforced in the existing CI job. Published 0.1.19 locally filters Python test runner choices using unambiguous CI commands after 0.1.18 remotely selected pytest for a unittest-gated repository; its exact-tag Python suite, distribution check and clean registry pipx install passed. Registration requires a preview and approval of generic fields before they may be sent to OpenRouter. The bundled coding skills and agent-spawn advice remain opt-in. Neither macOS runtime nor a repeatable speed or quality gain is verified. The first four synthetic CLI pairs tied on blind quality; later focused evidence was mixed. See [PILOT.md](PILOT.md) for observations and [TASKS.md](TASKS.md) for task/commit tracking.

## Efficacy study: 20 matched cases

Design eight planning tasks, six subagent tasks, and six routine controls spanning Desktop and CLI where feasible. Run randomized equivalent baseline/advisor arms with the same model/settings and freeze blind quality scores before opening diagnostic arm mappings. For each case, assess advice relevance and availability, required checks, blocks, data minimization, and time to the first **productive** action. Compare paired outcomes and collect safe latency metrics. The first four synthetic CLI pairs tied in blind quality; later focused results were mixed. A 0.1.19 P01 pair had a post-unblind scoring correction and missing required-test receipts, so it cannot establish blinded efficacy. The subsequent CLI pilot parser separates recognized test invocations and completions from an observed exit for future pairs; old receipts cannot be retroactively resolved. The sample remains small.

Adoption targets: zero blocks or disclosures; zero omitted required checks; at least 80% useful advice; at least 90% coverage of eligible events; remote Jev p95 below two seconds; and better time to first productive action. If remote selection does not help, keep the local catalog and explicit command while disabling automatic remote choice. Count manual `recommend` trials separately. Do not infer a task from the unsupported default-role subagent transcript or silently change Codex's permission policy.

## Product candidates after measured results

1. **Better relevance:** use blinded negative cases to refine local classification and reviewed `use_when`/`avoid_when`. The opt-in spawn advisor is source-tested on one CLI child using a descriptive task name; run matched useful-action trials and Desktop coverage before considering default enablement. Keep generic-shell singleton abstention. A clean profile has no reviewed API-design skill and correctly stays silent there. The optional two-skill prototype remains explicitly opt-in and experimental. v0.1.16 adds conditional matching-skill guidance from PR #63; a source-built C05 pair read `create-plan` but tied 6/7 on blind scores. This does not demonstrate speed or quality benefit. The installer ships as an explicit experimental opt-in after artifact and CI gates; require stronger task and Desktop evidence before recommending it broadly or enabling it by default. Never install a skill silently or claim that a configured MCP tool is callable.
2. **Coding workflow:** trial test ordering, error triage, and task priority based on coarse metadata with explicit criteria. Repository-required tests and real exit codes remain authoritative. Enable only after matched tasks show value and the data sent to Jev remains safe.
3. **Platform support:** document host-specific hook event schemas and trust behavior after macOS and Linux validation; keep Windows as a separately tracked idea, not a supported platform promise.
4. **Packaging and distribution:** production PyPI publication for `acidkill/JevCompass` completed through [workflow run 36114012972](https://github.com/acidkill/JevCompass/actions/runs/36114012972), using `pypi.yml` and the `pypi` environment, from tag commit `7e44137f3471532dfbf74d7a61c0e8946a58062f`. PyPI JSON reports wheel SHA-256 `b4331c437f1b193ffd50a3da60dcf6105e0cb50b6f085f4745f14cd5ec1bcd7a` and sdist SHA-256 `a066bef4c3fd700b938e1b9f705556d755a4d423e33a92a5653c4b6f22e27303`. A fresh isolated pipx install from the registry succeeded; `doctor` passed with the two default hooks and no `PreToolUse` gate. Continue to verify other Python versions and macOS separately before making those platform claims. TestPyPI remains a distinct `release.yml` workflow and `testpypi` environment with its own publisher and approval. The repository is licensed under Apache 2.0.
5. **Later integrations:** consider narrowly scoped permission-request advice or native Codex plugin packaging only if the advisor shows value. Any permission feature needs opt-in, separate privacy and regression tests, and must preserve Codex approval; do not restore broad `PreToolUse` gates.

Each feature moves into a release only with its own tests and host-visible evidence. JevCompass remains optional guidance, never an authority for permissions, skill use, or required validation.
