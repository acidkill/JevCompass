# JevCompass roadmap

**Read by stage:** [current pilot evidence](PILOT.md) · [20-case design (not execution)](PILOT_CASES.md) · [release/task receipts](TASKS.md) · [quick start](README.md).

The Apache-2.0-licensed [GitHub releases](https://github.com/acidkill/JevCompass/releases) contain a reviewed local catalog, two default non-blocking Codex hooks, optional OpenRouter Decisions ranking, explicit recommendations, the `history` category, an installer, and diagnostics. v0.1.15 also includes the security candidate filter from PR #45, with agent-spawn advice disabled by default; confirm the release page and [task ledger](TASKS.md) for artifact verification. The tagged artifact and subsequent main-branch documentation changes are tracked separately. This roadmap tracks evidence and capabilities needed for broader adoption. JevCompass v0.1.15 is published on PyPI; that does not establish end-to-end macOS support or that ranking improves task outcomes. The v0.1.16 release candidate's conditional matching-skill guidance and optional bundled-skill installer are source-only and experimental. One source-built C05 pair read `create-plan` and tied 6/7 on blind scores; this is not evidence of a speed or quality benefit. The initial four synthetic CLI pairs (P01, P03, P05, P07) tied on blind quality; later focused P05 pairs produced one baseline win and one treatment win. See [PILOT.md](PILOT.md) for observations and [TASKS.md](TASKS.md) for task/commit tracking.

## Release evidence to complete

- **Desktop prompt delivery:** open a new Desktop session, confirm each hook in `/hooks`, and submit a substantive task. Record the advice ID visible in the agent's context *before its first tool* and correlate it with `~/.local/state/jevcompass/advisor.jsonl`. A metric alone proves adapter execution, not agent delivery. A named-role Desktop `explorer` smoke previously reported ID `19b24b54` before first tool; it does not prove prompt delivery, worker behavior, coverage, or benefit. Separate host invocation failures from intentional adapter abstention or low-signal singleton shell advice.
- **macOS runtime:** on current macOS Codex Desktop and CLI, verify fresh pipx installation, Python 3.11 and a recent Python version, hook trust and reloading, keyring behavior, optional OpenRouter choice, and unattended fallback. The lightweight PR check now uses one Linux `ubuntu-slim` container with Python 3.11; macOS is validated separately before a platform claim. Earlier six-job CI runs stopped before steps with GitHub's payment-or-spending-limit annotation, while the private repository's Actions budget was capped at $0 with spending stopped. Public hosted CI passed all 177 tests on [PR #3](https://github.com/acidkill/JevCompass/pull/3); macOS validation remains separate. A green local Linux result does not certify macOS.
- **Usability:** a fresh public clone of main `db7a0d3` installed from source with isolated pipx and `CODEX_HOME` on Linux; `recommend`, `install --dry-run`, `install`, and `doctor --json` passed with exactly the two advisory hooks and no PreToolUse gate. This is a setup smoke, not agent-visible delivery or macOS verification. Next confirm coexistence with existing hooks and routine shell, Git, Helm, and network behavior on representative host sessions.
- **Artifact quality:** build wheel and sdist from the exact release commit, inspect members for secrets/private paths, run the full suite, and install with pipx from the built wheel. Repeat for each public candidate. The tagged v0.1.14 release passed 224 Python 3.11 tests from an exact-source archive, distribution-content auditing, independent download digest checks, and isolated pipx installation. `doctor` confirmed two default hooks and a reversible optional spawn-only hook; a clean synthetic CLI child received the opt-in context before its first tool. macOS remains unverified. Subsequent commits require new evidence.
- **Privacy:** keep synthetic Decisions request checks showing only category, role, domain, and generic candidate metadata. Never send raw prompts, source, paths, memory, client records, or private skill descriptions. Keep any diagnostic traces locally redacted.

## Efficacy study: 20 matched cases

Design eight planning tasks, six subagent tasks, and six routine controls spanning Desktop and CLI where feasible. Run randomized equivalent baseline/advisor arms with the same model/settings and freeze blind quality scores before opening diagnostic arm mappings. For each case, assess advice relevance and availability, required checks, blocks, data minimization, and time to the first **productive** action. Compare paired outcomes and collect safe latency metrics. The first four synthetic CLI pairs tied in quality; later focused results were mixed and remain a small sample.

Adoption targets: zero blocks or disclosures; zero omitted required checks; at least 80% useful advice; at least 90% coverage of eligible events; remote Jev p95 below two seconds; and better time to first productive action. If remote selection does not help, keep the local catalog and explicit command while disabling automatic remote choice. Count manual `recommend` trials separately. Do not infer a task from the unsupported default-role subagent transcript or silently change Codex's permission policy.

## Product candidates after measured results

1. **Better relevance:** use blinded negative cases to refine local classification and reviewed `use_when`/`avoid_when`. The opt-in spawn advisor is source-tested on one CLI child using a descriptive task name; run matched useful-action trials and Desktop coverage before considering default enablement. Keep generic-shell singleton abstention. A clean profile has no reviewed API-design skill and correctly stays silent there. The optional two-skill prototype remains explicitly opt-in and experimental. The v0.1.16 candidate adds conditional matching-skill guidance from PR #63; a source-built C05 pair read `create-plan` but tied 6/7 on blind scores. This does not demonstrate speed or quality benefit. Release the installer only as an explicit experimental opt-in after artifact and CI gates; require stronger task and Desktop evidence before recommending it broadly or enabling it by default. Never install a skill silently or claim that a configured MCP tool is callable.
2. **Coding workflow:** trial test ordering, error triage, and task priority based on coarse metadata with explicit criteria. Repository-required tests and real exit codes remain authoritative. Enable only after matched tasks show value and the data sent to Jev remains safe.
3. **Platform support:** document host-specific hook event schemas and trust behavior after macOS and Linux validation; keep Windows as a separately tracked idea, not a supported platform promise.
4. **Packaging and distribution:** production PyPI publication for `acidkill/JevCompass` completed through [workflow run 36114012972](https://github.com/acidkill/JevCompass/actions/runs/36114012972), using `pypi.yml` and the `pypi` environment, from tag commit `7e44137f3471532dfbf74d7a61c0e8946a58062f`. PyPI JSON reports wheel SHA-256 `b4331c437f1b193ffd50a3da60dcf6105e0cb50b6f085f4745f14cd5ec1bcd7a` and sdist SHA-256 `a066bef4c3fd700b938e1b9f705556d755a4d423e33a92a5653c4b6f22e27303`. A fresh isolated pipx install from the registry succeeded; `doctor` passed with the two default hooks and no `PreToolUse` gate. Continue to verify other Python versions and macOS separately before making those platform claims. TestPyPI remains a distinct `release.yml` workflow and `testpypi` environment with its own publisher and approval. The repository is licensed under Apache 2.0.
5. **Later integrations:** consider narrowly scoped permission-request advice or native Codex plugin packaging only if the advisor shows value. Any permission feature needs opt-in, separate privacy and regression tests, and must preserve Codex approval; do not restore broad `PreToolUse` gates.

Each feature moves into a release only with its own tests and host-visible evidence. JevCompass remains optional guidance, never an authority for permissions, skill use, or required validation.
