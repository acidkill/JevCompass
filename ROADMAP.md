# JevCompass roadmap

JevCompass currently ships a private GitHub release for invited users, with a local reviewed catalog, two non-blocking Codex hooks, optional OpenRouter Decisions ranking, explicit recommendations, an installer, and diagnostics. This roadmap tracks evidence and capabilities needed for broader adoption. It is a plan, not a claim that the package is on PyPI, that macOS has been tested end to end, or that ranking improves task outcomes. The present release report contains four fresh synthetic CLI pairs (P01, P03, P05, P07); blind quality tied in all four. See [PILOT.md](PILOT.md) for observations and [TASKS.md](TASKS.md) for task/commit tracking.

## Release evidence to complete

- **Desktop prompt delivery:** open a new Desktop session, confirm each hook in `/hooks`, and submit a substantive task. Record the advice ID visible in the agent's context *before its first tool* and correlate it with `~/.local/state/jevcompass/advisor.jsonl`. A metric alone proves adapter execution, not agent delivery. A named-role Desktop `explorer` smoke previously reported ID `19b24b54` before first tool; it does not prove prompt delivery, worker behavior, coverage, or benefit. Separate host invocation failures from intentional adapter abstention or low-signal singleton shell advice.
- **macOS runtime:** on current macOS Codex Desktop and CLI, verify fresh pipx installation, Python 3.11 and a recent Python version, hook trust and reloading, keyring behavior, optional OpenRouter choice, and unattended fallback. CI declares macOS jobs for Python 3.11 and 3.14, but GitHub Actions has stopped jobs before steps due account billing. A green local Linux result does not certify macOS.
- **Usability:** test invited-user setup from private clone or digest-checked release wheel, validate `jevcompass install --dry-run`, `install`, `doctor`, and `recommend` on a clean profile. Confirm existing hooks remain, and routine shell, Git, Helm and network commands never become gated. Record any issue in the task list.
- **Artifact quality:** build wheel and sdist from the exact release commit, inspect members for secrets/private paths, run the full suite, and install with pipx from the built wheel. Repeat for each public candidate. The private v0.1.8 release passed local Linux release checks; new commits require new evidence.
- **Privacy:** keep synthetic Decisions request checks showing only category, role, domain, and generic candidate metadata. Never send raw prompts, source, paths, memory, client records, or private skill descriptions. Keep any diagnostic traces locally redacted.

## Efficacy study: 20 matched cases

Design eight planning tasks, six subagent tasks, and six routine controls spanning Desktop and CLI where feasible. Run randomized equivalent baseline/advisor arms with the same model/settings and freeze blind quality scores before opening diagnostic arm mappings. For each case, assess advice relevance and availability, required checks, blocks, data minimization, and time to the first **productive** action. Compare paired outcomes and collect safe latency metrics. Four early synthetic CLI pairs tied in quality and are only a small sample.

Adoption targets: zero blocks or disclosures; zero omitted required checks; at least 80% useful advice; at least 90% coverage of eligible events; remote Jev p95 below two seconds; and better time to first productive action. If remote selection does not help, keep the local catalog and explicit command while disabling automatic remote choice. Count manual `recommend` trials separately. Do not infer a task from the unsupported default-role subagent transcript or silently change Codex's permission policy.

## Product candidates after measured results

1. **Better relevance:** use blinded negative cases to refine local classification and reviewed `use_when`/`avoid_when`. Keep generic-shell singleton abstention. A clean profile has no reviewed API-design skill and correctly stays silent there. Consider an optional first-party skill pack only after synthetic installation, privacy review, and paired trials demonstrate gains. Never install a skill silently or claim that a configured MCP tool is callable.
2. **Coding workflow:** trial test ordering, error triage, and task priority based on coarse metadata with explicit criteria. Repository-required tests and real exit codes remain authoritative. Enable only after matched tasks show value and the data sent to Jev remains safe.
3. **Platform support:** document host-specific hook event schemas and trust behavior after macOS and Linux validation; keep Windows as a separately tracked idea, not a supported platform promise.
4. **Packaging and distribution:** confirm the reported production PyPI Trusted Publisher identity for `acidkill/JevCompass`, workflow `pypi.yml`, environment `pypi`. The report says pending; no upload or public artifact has been verified, and pending does not reserve the project name. Resolve the GitHub Actions billing gate, run the host matrix, recheck package name/version, repeat private-content audit and clean pipx installation, then make a separate explicit production publication decision. TestPyPI uses the distinct `release.yml` workflow and `testpypi` environment, with its own publisher and approval. Public package publication, source-repository visibility, and licensing are separate decisions.
5. **Later integrations:** consider narrowly scoped permission-request advice or native Codex plugin packaging only if the advisor shows value. Any permission feature needs opt-in, separate privacy and regression tests, and must preserve Codex approval; do not restore broad `PreToolUse` gates.

Each feature moves into a release only with its own tests and host-visible evidence. JevCompass remains optional guidance, never an authority for permissions, skill use, or required validation.
